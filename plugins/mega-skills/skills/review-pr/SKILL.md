# Ревью PR → фикс блокеров → пуш → вердикт

Аргументы: `$ARGUMENTS` — номер PR, опционально слово `security` для ревью только по безопасности.

## 1. Подготовка

- `gh pr view <PR>` и `gh pr diff <PR>`: понять цель PR и объём изменений.
- Вычекать ветку PR в отдельный git worktree, не трогая текущую рабочую копию.
- Перед тестами выполнить проверки из скилла `preflight` (Docker, APP_URL, изоляция БД).

## 2. Ревью

Проверить параллельно, по возможности отдельными субагентами:

- **Безопасность:** авторизация на новых эндпоинтах, XSS, SQL-инъекции, CSV formula injection, секреты и пароли в логах.
- **Контракт:** если PR в бэкенде или фронтенде, сверить с парным репозиторием — маршруты (`routes.ts`), поля API, коды ошибок, авторизацию. Эндпоинт, который вызывает фронтенд, должен существовать в main или в открытом PR бэкенда.
- **Корректность:** граничные случаи — дубли строк, дедлоки и транзакции, unix-time против DATE, часовые пояса (Москва), пустые и null значения.

## 3. Классификация

Нумерованный список находок, каждая помечена:

- **БЛОКЕР** — баг, уязвимость, сломанный контракт, потеря данных.
- **Не блокер** — стиль, рефакторинг, улучшения.

## 4. Исправление

- Исправлять только блокеры, если пользователь не просил иного.
- К каждому исправлению — регрессионный тест. Показать, что тест **падает** на старом коде и **проходит** на новом.
- Перед пушем: полный прогон тестов, PHPStan и phpcs для PHP, `npm run build` (бюджет бандла) для фронтенда.
- Изменения минимальные, без попутного рефакторинга.

## 5. Пуш и CI

- Запушить в ветку PR. Никогда не делать force-push и не мержить самому.
- `gh pr checks <PR> --watch`. Если джоба упала: `gh run view <run-id> --log-failed`, исправить, запушить, повторить (до 3 итераций).
- Не выносить финальный вердикт, пока CI не завершён. Если ждать нельзя — явно написать, что CI не подтверждён.

## 6. Вердикт

Коротко, в конце ответа:

```
Вердикт: МЕРЖИТЬ | МЕРЖИТЬ ПОСЛЕ <PR/условие> | НЕ МЕРЖИТЬ
Исправлено: <блокеры с SHA коммитов>
Осталось (не блокеры): <пронумерованный список>
CI: зелёный | упал на <джоба> | не дождался
Порядок деплоя: <если зависит от других PR: backend → gateway → frontend>
```
